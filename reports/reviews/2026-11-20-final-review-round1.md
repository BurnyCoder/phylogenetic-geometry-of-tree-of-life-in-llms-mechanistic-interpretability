**Scope.** The whole repository at commit `3453dde`: preregistration and deviations 1–19, README, `reports/summary.md`, `reports/paper.typ`, `results/RESULTS.md`, every `results/qwen35_2b/*/results.json`, the figures, and the analysis code (`analysis.py`, `stats/`, `stage2`–`stage6`, `probes/flat.py`, `causal.py`, `behavior.py`, `eco.py`, `examples.py`, `report.py`, `paper.py`, `simulate.py`, `data/tree.py`).

**What I ran.** CPU-only re-analyses with the repo venv, on the frozen data and the stored activations. Scripts are in the session scratchpad, not in the repo. Every number below marked "(reviewer re-analysis)" comes from those runs. All of them are **post hoc** and must be labelled as such if adopted.

## Verdict in one paragraph

The preregistered primary result (H1) is computed correctly and is robust. It survives every additional check I tried:
- removing triplets that share any token;
- restricting to triplets on which character n-grams have no preference;
- linearly residualizing popularity and name length out of the representation.

The problems are in the **secondary and exploratory claims and in how they are worded**:
1. The flat-probe headline (r = 0.749, "a small linear subspace carries the tree") is fully explained by coarse-class structure. A class-blob input with no within-group tree structure scores *higher* (0.835).
2. The "ranks species within a group" evidence uses a pooled metric that a stratum-only predictor already saturates.
3. S2 is matched by the untrained random-init Qwen.
4. The "folk beats phylogeny" conflict result is indistinguishable from untrained networks.
5. The generated reports and the public site present the superseded causal numbers as the "final run".
6. The causal readout deviates from the registration without a logged deviation.
7. The registered BH-FDR correction for exploratory tests was never applied.

## Must fix (each could invalidate or materially overstate a claim)

### M1. The flat-probe headline is explained by coarse classes; the controls are too weak

- **Where:**
  - README.md:25 ("A small linear subspace carries the tree … far better than a shuffled-tree probe or … GloVe");
  - README key-results row (generated by `report.py:360-364`);
  - `reports/paper.typ:21-22` (abstract), `:175-176` (Discussion claim 2), `:194-195` (Conclusion: "carried by a low-dimensional linear subspace");
  - `reports/summary.md:36`.
- **Evidence:**
  - The probe target is edge-count path length over *all* species pairs (`stage2.py:61,137`), so held-out test–test pairs include cross-stratum pairs.
  - A predictor that knows **only the 13 strata**, assigning each pair the mean path length of its stratum pair, correlates with path length at Pearson **0.871** (reviewer re-analysis; the class rank gives 0.876, the order rank 0.978). That is the ceiling for a class-only representation, and it is above the probe's 0.749.
  - A practical control is the probe pipeline itself (`train_probe`, `family_folds`, PCA fit on the training fold, k = 10, 2,000 steps, seed 0) run on `stage2.matched_class_blob(V)`. That input is each species placed at its stratum centroid plus isotropic noise with the real per-stratum spread, so it carries **no within-stratum tree structure**. It reaches held-out test–test **r = 0.835**. On the same seed, the model's layer-6 vectors reach r = 0.736 (reviewer re-analysis).
  - The registered controls cannot detect this:
    - the shuffled tree destroys class structure, so it scores about 0;
    - the random-init inputs carry no class structure (r = 0.016);
    - GloVe clusters classes weakly (0.405).
- **Why it matters:** The headline probe number, and its comparison with every control, measures how well the representation separates the 13 coarse groups, not phylogeny. "Carries the tree" and the abstract's framing are not supported.
- **Fix:**
  - Add the matched class-blob input as a probe control in stage 2. The function already exists and is unused for the probe.
  - Report the class-only ceiling (0.871).
  - Lead with a within-stratum metric (see M2), not test–test r over all pairs.
  - Reword README.md:25, the abstract, Discussion (2) and the Conclusion accordingly.
  - Add the class-blob bar to `probe_heldout_r.png` (`report.py:426-448`).

### M2. The "probe ranks species within groups" evidence uses a pooled metric that a stratum-only predictor saturates

- **Where:**
  - `probes/flat.py:283-286` (`test_test_within_group_spearman` pools all same-stratum pairs into one Spearman);
  - `reports/paper.typ:148` ("within-stratum held-out Spearman … 0.351 (shuffled-tree control 0.034), so the probe captures order inside strata, not only stratum membership");
  - README.md:25 ("It also ranks species *within* a group");
  - stage 6 `probe_seed.test_test_within_group_spearman` (0.338).
- **Evidence (reviewer re-analysis):**
  - Strata differ in their typical within-stratum path length: molluscs and crustaceans span deep splits, birds do not. Pooling across strata therefore rewards any representation whose within-stratum *spread* differs by stratum. This is a Simpson-type artifact.
  - A predictor that gives every within-stratum pair the **mean within-stratum path length of its stratum**, with zero within-stratum ordering, has pooled within-group Spearman **0.352**. That equals the reported 0.351.
  - The class-blob probe input from M1 gets pooled 0.204, but **mean per-stratum Spearman −0.002**.
  - The model's probe gets mean per-stratum Spearman **0.282** (seed 0).
  - So with a correct metric the model probably does carry within-stratum order. However, the raw layer-6 cosine distances *without any probe* already give a mean per-stratum Spearman of 0.290. The probe therefore adds nothing over the raw geometry.
- **Fix:**
  - Compute Spearman within each stratum and average, weighted by number of pairs or of nodes. Alternatively, rank-transform within stratum before pooling.
  - Report it next to the class-blob control and the raw-distance value.
  - Rewrite `paper.typ:148` and README.md:25.

### M4. "Folk beats phylogeny on conflict cases" is indistinguishable from untrained networks and lexical similarity

- **Where:**
  - README.md:32 ("significantly more often than the tree");
  - the key-results row verdict "follows the folk/ecological partner" (`report.py:357-359`, which keys on p < 0.05 vs 0.5 only);
  - `paper.typ:24-25` (abstract), `:124-125`, `:178`;
  - `summary.md:39` ("ecology wins on conflicts").
- **Evidence (from `conflict/conflict.json`):**

  | Representation | Tree-closer partner chosen | Binomial p |
  |---|---|---|
  | Qwen3.5-2B (layer 6) | 11/36 | 0.029 |
  | random-init Qwen3.5-2B | 13/36 | 0.13 |
  | Pythia-410m step 0 | 13/36 | 0.13 |
  | char-3-grams | 9/36 | 0.004 |

  - Exact McNemar test, Qwen vs random-init: discordant 7 vs 9, **p = 0.80**. Vs Pythia step 0: 5 vs 7, p = 0.77 (reviewer re-analysis).
  - Splitting by conflict type, neither subset is significant for Qwen: lexical types 4/14 (p = 0.18); non-lexical types 7/22 (p = 0.13; random-init 10/22).
  - The 36 triplets are not independent. "human" is the tree-closer partner in 5 triplets, "African bush elephant" in 4, "red kangaroo" in 3, and "common starfish" is an anchor twice.
  - The folk partners were curated to be lexically or ecologically close ("whale shark" for "blue whale", "common octopus" for "common starfish").
  - The test is exploratory, and the registered BH-FDR correction was not applied (see M7).
- **Why it matters:** The pattern is equally present in untrained networks. It therefore reflects the curated set's surface similarity, not a learned folk or ecological taxonomy. "Ecology wins" in particular has no support: most conflict types are lexical or folk-class types.
- **Fix:**
  - Report the control rows and the McNemar comparison.
  - Change the verdict to "no evidence that the trained model differs from untrained networks". Keep "the geometry does not follow the tree on these cases" as a descriptive statement.
  - Apply BH and drop "significantly" unless the result survives.
  - Use a cluster-aware test (e.g. a permutation that respects shared anchors) if a p-value is kept.

### M6. The causal readout deviates from the registration without a logged deviation, and C-abl as designed tests class information, not phylogeny

- **Unlogged deviation:**
  - Registered (`preregistration.md:186-187`): "log-probability of the correct class word in `The {name} is a kind of ___`", on the "stage 2 flat probe" subspace.
  - Implemented (`behavior.py:160-161`, `stage3.py:212`): a chat question, "What kind of animal is the {name}? Choose one of: amphibian, …, reptile. Answer with one word." It is scored as a softmax over 11 candidate words, each by full-sequence log-probability.
  - The subspace is also a *new* probe fit on half of the families (`stage3.py:203-206`), not the stage-2 probe.
  - Deviation 19 does not mention any of this. These choices are defensible, but they must be logged before the rerun is reported as confirmatory.
- **Design limitation:**
  - The probe subspace is trained on all-pairs path length, which is dominated by coarse class (M1: class-only ceiling r = 0.871).
  - The readout is the **class word**, i.e. the folk category the primary metric was built to exclude.
  - A positive C-abl or C-swap result would therefore show that the subspace carries *class* information the model uses. It would not show that a phylogenetic geometry is causally used.
  - The variance-matched random subspaces do not control for this, because they are not class-aligned.
- **Fix, before the rerun is written up:**
  1. Log the prompt, scoring and probe-refit choices as a deviation, dated before the rerun.
  2. Add a class-only subspace control: a k = 10 probe trained on the class-oracle distance, or a 10-d LDA subspace of strata. Report whether the phylogeny probe's effect exceeds it.
  3. Name the subspace "probe subspace (class-dominated)" rather than "phylogeny subspace" unless (2) favours it.
  4. If possible, add a readout that needs within-class structure, e.g. order-level questions within mammals and birds.
- **Disclosure:** In the first run the probe beat *all* random subspaces (both rank p at their floors; species-level Wilcoxon p = 2.9e-5). The rerun decision was therefore made after seeing a favourable direction. The floor problem is real, so the rerun is justified, but both runs should be reported side by side and this conditional decision stated.

### S3. The habitat-axis wording overclaims

### S4. "No time signal" should be "no time signal detected", and the S5 test has low power by design
- The pooled partial Spearman is weighted by pair counts. That weighting is dominated by cross-stratum bins: "none" 34,025 and "phylum" 32,430 of 75,318 dated pairs.
- The null permutes species *within strata* (`analysis.py:102`), which keeps stratum-pair structure, so those bins contribute almost no power.
- In the phylum bin, age and LCA depth correlate at −0.9988. The partial correlation there divides by about 0.05 and is noise-amplified.
- **Fix:**
  - Rephrase README.md:31 and `summary.md:38`.
  - Report the within-stratum bins (class, order, family, genus) separately with the same null.

### S5. The binomial ablation compares against an inflated common-name number
- The comparator "common names on the same triplets 0.530" (README.md:54, `stage4.py:84-88`) includes triplets with shared head nouns.
- On the same genus-split triplets made head-noun-disjoint (10,950), common names give **0.476**.
- Binomials are not structureless. They rise to 0.386 at layer 20, with max-T over 25 layers p = 0.050 (299 permutations; reviewer re-analysis). With the head-noun-disjoint mask the value is 0.380 (p = 0.13).
- Replace "carry no structure" (README.md:35, `summary.md:44`) with "much weaker, late-layer only".

### S6. Ecological and body-size similarity is an uncontrolled confound of H1
- Within strata, ecology, diet and body size are phylogenetically conserved, and the project itself shows that ecology is strongly encoded.
- H1 cannot separate "tree-consistent" from "phylogenetic".
- Either add an EltonTraits trait-distance baseline for the primary mammals and birds (diet, foraging stratum, body mass; the data is already downloaded), or describe the H1 result as "agreement with the tree" rather than "phylogenetic knowledge".

  - only 40 simulations per cell;

  - the null cell has mean 0.323 and size 0/40;

## Major claims checked and found sound

1. **H1 computation matches the registration.**
   - Triplet scoring, including tie handling (`triplets.py:80-89`).
   - Resolved-triplet sampling at polytomies.
   - Node balancing.
   - Within-stratum and head-noun-disjoint masks.
   - Max-T with the same within-stratum permutation applied to all layers, and the p formula.
   - Family-blocked cross-fitting.
   - Paired family-block bootstrap with the same draws for all representations.
   - The fixed required-control set, and the criteria logic (`analysis.py:234-246`).
2. **Robustness of H1** (reviewer re-analysis, post hoc):

   | Check | Qwen TA_within | Untrained controls | Paired CI vs controls |
   |---|---|---|---|
   | No shared token (9,486 triplets) | 0.478 | random-init 0.377, step 0 0.391 | not computed |
   | Char-3-gram ties | 0.485 | — | exclude 0 (S1) |
   | Popularity, token count, word count and name length linearly residualized out of the species vectors (within strata, **with centred covariates**) | 0.460 at layer 6; cross-fitted 0.462 | — | random-init [0.025, 0.166]; Pythia step 0 [0.015, 0.150] |

   - A first attempt with uncentred covariates shifted the origin. Because cosine distance depends on the origin, that wrongly suggested fragility. Anyone repeating the residualization must re-centre.
   - Stage 6 (triplet seeds, K per node, template subsets, single templates, 80% subsamples, cross-fit seeds) also agrees, checked against `stage6/results.json`.
3. **Null calibration.** Under a class-blob null the node-balanced TA_within is unbiased: 0.3347 ± 0.0014 over 200 simulations.
4. **Holm adjustment of S1–S5.** Checked by hand: 0.005, 0.005, 0.360, 0.360, 0.360. The S3/S4/S5 "not supported" verdicts follow the registration.
5. **Mantel max-T.** The rank-once shortcut is valid, because row and column permutation preserves the multiset of the upper triangle.
6. **Timing of the preregistration** (git history).
   - Fixes for deviations 11–18: `95b1468` and `bb4afd0`; deviations logged and species set re-frozen: `ef513d7`. All come before the stage-1b results in `bb75e4b`.
